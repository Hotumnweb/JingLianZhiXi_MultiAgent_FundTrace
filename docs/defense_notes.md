# 答辩讲解要点与能力边界（v1.1）

> 这份文档回答三个问题：
> 1. 现在平台里到底有哪些“可操作、可证明”的能力；
> 2. 评委问“这就是元智能体吗”时怎么回答；
> 3. 下一步怎样把“固定流水线”升级成真正的工具调用元智能体。
>
> **完整演示步骤（点哪里/看什么/说什么）见 [DEMO_SCRIPT.md](DEMO_SCRIPT.md)。**

---

## 一、先讲清楚：这不是“一个模型”，而是一套多智能体调度系统

| 节点 | 职责 | 当前实现 |
| :--- | :--- | :--- |
| Node1 调度中心 | 任务接收、调度决策、状态管理、调用记录、结果归档 | Streamlit + LangGraph Supervisor + 任务队列 |
| Node2 GPU 算力中心 | 任务规划/研判报告生成 | Ollama + Qwen3.5-9B-tools（Q4_K_M，约 35~47 tok/s） |
| Node3 工具与图数据 | 流水解析、建图、图规则查询 | pandas + Neo4j 5.26（3,492 账户 / 42,175 转账） |

**现场一句话**：
> “第一台只负责调度和记录，第二台负责 AI 推理，第三台负责图数据和图算法；
> 三台机器通过内网 HTTP / Bolt 协作，数据不出内网。”

## 二、现在平台里真正能操作、能证明的能力

| 能力 | 在哪里操作 | 能证明什么 |
| :--- | :--- | :--- |
| 任务下发 / 队列 / 重跑 | 元智能体调度、任务队列 | 调度中心不是静态展示，能真实执行任务 |
| 元智能体自主选工具 | 元智能体自主分析 | Qwen3.5 通过 tools 自主选择归集/快进快出/账户往来等工具，Node1/Node3 执行后回传，展示决策轨迹 |
| 子智能体调用记录 | 任务详情 → 子智能体调用记录 | Node1/Node2/Node3 分别做了什么、耗时多少 |
| 中间结果汇总 | 任务详情 | 解析条数、图谱规模、证据数量可追溯 |
| 追加侦查指令 | 任务结果 / 任务详情 | 在同一任务上继续追问，体现人机协同 |
| 真实数据接入与清洗 | 数据接入 | 现场吃 453 MB 混乱原始流水：自动识编码/分隔符/列名、复合账号、流式清洗，直接建图；回答“是不是只会用内置数据” |
| Neo4j 只读操作台 | 左侧“Neo4j 操作台” | 现场执行 Cypher，展示图谱规模、入度、快进快出、账户往来 |
| 图规则重算 | 规则与指标 | 精确率/召回率/团伙召回可现场复算 |
| 报告与证据下载 | 研判报告 | 报告 + 证据 JSON 可复核、可复现 |
| 断网自检、节点状态 | 节点与工具 | 内网闭环部署、三节点在线状态 |

### Neo4j 操作台现场演示（建议 60 秒）

1. 打开“Neo4j 操作台”；
2. 选择“Top 入度账户（上游≥4）”→ 执行，看到 `ACC_00745` 等 97 个上游的归集结构；
3. 选择“快进快出（48h / 95%）”→ 执行，看到过渡账户命中；
4. 选择“账户资金往来（ACC_01978）”→ 执行，展示具体交易；
5. 选择“约束与索引”→ 执行，展示 `account_id_unique` 唯一约束；
6. 说明：这里只允许只读查询，写操作必须走任务流程/Neo4j Browser，避免误改演示数据。

### 真实数据接入现场演示（建议 90 秒，回应“只会用内置数据”）

1. 打开“数据接入”页，数据源选 `data/new/one/HI-Small_Trans.csv`（453.6 MB，507 万行）；
2. 平台自动识别 UTF-8、逗号、11 列、表头，并把“银行号 + 账号”拼成复合账号；
3. 点“预览清洗结果”→ 前 10 万行约 2 秒清洗完成，展示剔除原因（自转账/空账号/重复）；
4. 点“在调度页用这份数据建图”→ 建图、规则、报告一条龙；
5. 口径：标签不进模型、原始文件只读、清洗报告可追溯；全量 508 万行赛后跑，现场 10 万行保节奏。
   详见 [DATA_CLEANING_GUIDE.md](DATA_CLEANING_GUIDE.md)。

## 四、评委问“这就是元智能体吗？”——诚实回答

**当前版本的准确定位**：
> “元智能体调度”页走的是“Supervisor 固定流水线 + Node2 大模型报告节点”的稳定演示链路；
> 新增的“元智能体自主分析”页已经真实跑通 Qwen3.5 的 tool-calling：
> 模型自己选择工具 → Node1/Node3 执行 → 结果回传 → 模型继续决策/总结。
> 也就是说，**工具调用能力已经验证，但尚未接入主任务队列/固定流水线**。

**不要硬吹**：如果评委追问“谁决定调用哪个工具”，当前回答是：
> “主流程由 LangGraph Supervisor 按任务状态做确定性路由，保证现场稳定；
> 自主分析实验台由 Qwen3.5 自己决定调用哪个工具，已经能跑通 plan → act → observe → summarize。
> 下一步会把这条工具调用链接入任务队列，替代固定的三步路由。”

**升级方向（按优先级）**：
1. **工具调用接入主流程（最重要）**：把 `parse_flow`、`run_graph_rules`、`query_cypher`、
   `write_report` 作为工具，由元智能体自主编排；实验台已验证可行；
2. **动态任务规划**：任务开始时先让 Node2 输出侦查计划，再执行；计划与实际调用都写入任务队列；
3. **失败重规划**：工具报错/证据不足时，由元智能体决定是否换查询或补充规则；
4. **Neo4j 操作台**：已提供只读 Cypher 现场操作，可继续增加“查询历史、结果导出、查询模板”；
5. **Jupyter（可选）**：适合技术附录/数据探索，不建议作为现场主流程；现场用平台内操作台更稳定。
   若需要，可增加 `notebooks/` 下的分析笔记本，展示 pandas/Neo4j 探索过程。

## 五、当前明确短板（评委可能追问）

- 主任务调度仍是固定流水线，不是 AI 全程自主规划；
- 工具调用实验台已经跑通，但轨迹还没有并入任务队列的正式记录；
- 任务拆解只有三个阶段，复杂任务/异常任务的动态分支还不够；
- Node2 目前直接调用 Ollama tools，Qwen-Agent 的 8010 服务尚未接入；
- Neo4j 操作台是只读的，写操作未开放（演示数据安全优先）；
- 工具调用决策轨迹目前展示在实验台，还没有升级成可视化决策树。

**结论**：平台、数据、工具调用原型已经能支撑演示；
下一步把“自主分析”接入主任务队列，就能从“数据管道 + 大模型报告”升级为真正可解释的元智能体。

## 六、四人现场分工（1 人主讲 + 3 人各操作一台电脑）

> 依据竞赛规程（附件 1）：
> - 第 7 页：学生组各赛道为团体赛，参赛选手 **2–4 名**，指导教师 1–2 名；
> - 第 10 页：评分权重为 **技能水平 60%、职业素养 10%、应用价值 10%、团队合作 10%、创新创意 10%**，
>   并要求“按团队成员分工，同步进行技能操作和现场讲解”。
>
> 你们 4 人正好取上限：主讲不抢操作，三个人分别守住 Node1 / Node2 / Node3 三台电脑。

### 角色总表

| 人员 | 位置/电脑 | 核心职责 | 必须会做的动作 |
| :--- | :--- | :--- | :--- |
| 主讲（建议兼队长） | 不占电脑，站在三屏中间 | 节奏、串词、价值表达、Q&A 统筹 | 开场、每个环节的转场提问、最后总结 |
| 操作员 A | Node1 调度电脑 | 平台主流程，操作最多 | 加载目标、输入指令、下发任务、任务队列、追加指令、报告下载 |
| 操作员 B | Node2 GPU 电脑 | 算力与模型服务 | `nvidia-smi`、`ollama ps`、`check_llm.py` / `/api/chat` 实测、报告生成时观察 GPU |
| 操作员 C | Node3 图数据电脑 | 图谱与 Cypher | Neo4j Browser 图形视图、账户往来查询、约束/索引、平台 Neo4j 操作台 |

### 6 分钟分工脚本（可按现场压缩）

| 时间 | 谁 | 动作 | 讲解要点 |
| :--- | :--- | :--- | :--- |
| 0:00-0:40 | 主讲 | 开场，指向三块屏幕 | “第一台调度、第二台算力、第三台图数据，内网闭环。” |
| 0:40-1:10 | 操作员 A / B / C | A 刷新节点；B 展示 GPU 和模型；C 展示图谱规模 | 三台机器同时在线，模型已加载，图谱可查 |
| 1:10-1:40 | 操作员 A | 选择数据源 → 加载目标 → 输入侦查指令 | “先确认实际条数和格式，再下达任务” |
| 1:40-3:00 | 操作员 A 主操作，B 观察 | A 下发并立即执行；B 在 GPU 电脑看 `nvidia-smi` | A 讲阶段/日志；B 报“GPU 已占用、模型正在推理” |
| 3:00-3:40 | 操作员 C | Neo4j Browser 执行账户往来查询并切图形视图 | “节点是账户，箭头是 TRANSFER 关系，图谱不是截图。” |
| 3:40-4:20 | 操作员 A | 任务队列 → 调用记录 → 追加侦查指令 | “每个子智能体调到哪个节点、耗时多少、产出什么，都可追溯。” |
| 4:20-4:50 | 操作员 A / 主讲 | 打开“元智能体自主分析”，启动一次 | “模型自己选工具，Node1/Node3 执行，再把结果回传。” |
| 4:50-5:30 | 操作员 A / C | 规则指标复算、报告与证据下载 | “精确率/召回率现场算；报告有证据 JSON，可复核。” |
| 5:30-6:00 | 主讲 | 收束 | “三机协同、工具调用、可解释、可复现；下一步接入任务队列。” |

### 主讲人不要做的事

- 不要抢操作员的鼠标/键盘；需要操作时明确说“请操作员 A 执行……”；
- 不要替操作员回答所有技术问题；用“这个问题请 Node2 操作员回答”把团队能力展示出来；
- 不要背 PPT；每页只讲“为什么做、怎么做、结果是什么”。

### Q&A 分工

- 总体架构 / 应用价值 / 创新点：主讲；
- 任务队列、平台流程、数据源与报告：操作员 A；
- 模型、GPU、Ollama、`think=false`、工具调用：操作员 B；
- Neo4j 图模型、Cypher、规则口径与指标：操作员 C；
- 遇到答不上来的：主讲接住并转给对应操作员，不要让沉默超过 3 秒。

### 赛前彩排

- 三个人各守一台电脑，完整走 2 遍 6 分钟流程；
- 操作员 A 练到不用看按钮位置；B 至少练熟 3 条命令；C 至少练熟 3 条 Cypher；
- 准备降级方案：Node2 离线时，A 说明平台会自动降级为规则模板报告；
- 每台电脑桌面只留演示窗口，贴好 Node1/Node2/Node3 标签。
