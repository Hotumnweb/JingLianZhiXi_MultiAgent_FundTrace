预期：`服务检查通过`、回复“连接正常”、约 30–50 tok/s。

## 2. 标准演示流程（8 分钟版，推荐）

> 分工建议：**主讲不碰键盘**；Node1 操作员负责平台，Node2 操作员盯 GPU/模型，
> Node3 操作员负责 Neo4j Browser/图谱。以下“操作”默认由 Node1 操作员执行。

### 2.1 调度总览（0:00–0:30）

**操作**：打开平台，默认进入“调度总览”。

**画面**：6 个 KPI（交易流水、图账户、可疑账户、归集、环形链、快进快出）、任务队列状态、
三节点集群卡、图规则命中分布、证据强度排行、最近一次研判。

**讲词**：
> “第一台是调度中心，只做任务下发、调度决策、状态管理和结果汇总；
> 真正推理在第二台 GPU，图数据和规则在第三台。三台机器内网协作，数据不出内网。”

**注意**：演示前若清空过数据，KPI 显示 `—`，属正常；跑完第一个任务后会自动填充。

### 2.2 内置 AML 全链路 + AI 报告（0:30–2:20）

**操作（Node1 操作员按顺序点）**：

1. 左侧导航点“**元智能体调度**”；
2. “流水数据源”选默认的“内置数据｜合成 AML 数据集 · 42,175 笔（内置）”；
3. 点“**加载目标数据**”，出现成功提示“目标已加载：42,175 条 · AML 标准格式”；
   （可展开“数据预览（前 8 行）”快速展示列结构）
4. “指令模板”选“**全量资金穿透分析**”（自动填入描述），也可保留默认描述；
5. 确认“**执行 AI 研判报告**”开关为开；右侧应显示“推理服务：在线 · qwen3.5-9b-tools:q4km”；
6. 点“**下发并立即执行**”；
7. 观察右侧：
   - 阶段卡依次点亮：主控调度 → 流水解析 → 账户关联 → 研判报告；
   - 进度条与“已用时”滚动；“调度日志”实时输出解析/图查询日志；
   - “AI 报告流式输出”逐 token 显示报告正文；
8. 完成后底部“任务结果”页签显示：可疑账户 **93**、归集 **10**、环形链 **12**、快进快出 **37**、
   报告状态“AI 生成”；
9. 可点“下载研判报告（Markdown）/ 下载证据 JSON”，或稍后到“研判报告”页展示。

**预期数字**：解析 42,175 条 → 图谱 3,492 账户 / 42,175 条转账 → 强证据 61、辅助 37、
去重可疑 93；报告约 25–40 秒（Node2 GPU，约 30–47 tok/s）。

**讲词**：
> “下发一次任务，Supervisor 先解析 4 万多条流水建图，再跑三条图规则，最后把结构化证据交给
> 第二台 GPU 生成研判报告；整个过程阶段、日志、token、耗时都可追溯。”

**若 AI 很慢或 Node2 离线**：关掉“执行 AI 研判报告”，点“仅执行图工具分析”（约 10 秒），
并说明“AI 不可达时自动降级为规则模板报告，链路不中断”。

### 2.3 规则与指标现场复算（2:20–3:00）

**操作**：左侧导航“**规则与指标**” → 点“**重新计算检测指标（约 10 秒）**”。

**预期结果**：

| 指标 | 数值 |
| :--- | :--- |
| 强证据合并（归集+环形） | 61 个账户 / 61 命中 / 精确率 **1.000** / 召回 0.462 |
| 强证据+辅助证据 | 93 个账户 / 76 命中 / 精确率 **0.817** / 召回 0.576 |
| 团伙级召回 | **22/22** 个洗钱团伙至少命中 1 个账户 |

**讲词**：
> “三条规则的口径和阈值来自离线评测；标签只用于事后算精确率/召回率，
> 智能体运行时看不到标签，避免拿答案破案。”

### 2.4 大数据抽样：IBM HI-Small（3:00–3:50）

**操作**：

1. 左侧导航“**数据资产**”；
2. 找到“IBM AML · HI-Small”卡片：
   - **现场生成模式**：点“生成/刷新抽样”，约 16 秒完成（讲解等待时间：抽样保留全部标签交易、
     正常交易固定种子抽样）；
   - **预生成兜底模式**：直接显示“已生成抽样 · 44,769 笔”；
3. 点卡片上的“**在调度页使用**”；
4. 自动跳到调度页且数据源已选中“大数据抽样｜IBM AML · HI-Small · 抽样 44,769 笔”；
5. 点“**加载目标数据**” → 显示 44,769 条、通用中文流水；
6. **关闭**“执行 AI 研判报告”，点“**仅执行图工具分析**”（约 6–10 秒）；
7. 结果：可疑账户 **65**（归集 5、环形链 5、快进快出 50）；
8. 回“数据资产”页，在“抽样样本规则评测”里确认数据集为 IBM HI-Small，点“**复算规则指标**”：
   - 强证据精确率 **1.000**、最终清单精确率 **0.600**；
   - **IBM 官方 8 类洗钱模式覆盖 8/8**（FAN-IN/FAN-OUT/CYCLE/BIPARTITE/STACK/RANDOM/
     GATHER-SCATTER/SCATTER-GATHER 均有账户命中）。

**讲词**：
> “这是 IBM 公开的 507 万笔银行流水，我们保留全部洗钱交易、对正常交易确定性抽样成 4.5 万笔，
> 建出 6.6 万账户的图谱。规则迁移后强证据命中全部是真实洗钱账户，8 类官方模式全部有命中；
> 账户级召回受模式覆盖限制，这也正是下一步规则扩充/调参的方向——数据是诚实的，
> 我们不只报对自己有利的数字。”

**注意**：抽样保留了全部标签交易，洗钱比例高于真实数据，讲解时主动说明这是“为现场可见性
做的抽样”。

### 2.5 真实原始数据接入：453 MB 清洗 → 建图（3:50–5:40）

这一段专门回答“是不是只会用内置数据”。

**A. 先展示“格式混乱”（约 20 秒）**

1. 左侧导航“**数据接入**”；
2. “服务器数据文件”选“格式样例｜bank_flow_format_sample.csv（0.02 MB）”；
3. 画面自动识别：**gb18030 编码、分号分隔、5 列、有表头**；字段映射自动填好；
4. 点“**预览清洗结果（前 200 行）**”：读取 200 行、有效 189 行，剔除空账号/自转账；
5. 讲：“真实流水可能是 GBK、分号、金额带 ￥、日期格式混用，平台自动识别并清洗。”

**B. 再展示“数据很大”（约 60–80 秒）**

6. “服务器数据文件”切换为“原始大数据集｜HI-Small_Trans.csv（453.63 MB）”；
7. 自动画像：**utf-8-sig、逗号、11 列、有表头、约 5,078,346 行**；
   数据集类型提示“IBM AML 银行流水”；“银行号+账号”自动拼成复合账号；
8. 在“执行清洗”区：行数上限选“**5 万行**”，抽样方式“前 N 行（最快）”，
   保持“剔除自转账/块内去重”开启，输出名称可改为 `ibm_live_clean`；
9. 点“**执行清洗**”：进度条显示“已读取 / 已写出”行数，约 **1 秒**完成；
10. 结果显示（实测）：写出行数 **50,000**、账号数 **49,843**、耗时 0.7 秒、时间跨度
    2022-09-01~09-04；展开“清洗剔除明细”可见自转账剔除 **147,257** 行（IBM 前几小时大量
    Reinvestment 自转账，属正常）、空账号/重复等剔除原因与数量；
11. 点“**在调度页用这份数据建图**”；
12. 调度页点“**加载目标数据**” → 关闭 AI 报告 → “**仅执行图工具分析**”（实测约 **4–7 秒**）；
13. 结果页显示快进快出命中 **50** 个账户（图谱 49,843 账户 / 50,000 边）；
14. 打开“**图数据与工具**”页：展示刚建好的资金网络与证据排行（若强证据为 0，页面会自动
    回退展示“强证据+快进快出”子图，也可手动切换子图范围）；
15. 打开“**Neo4j 操作台**”：执行预设“图谱规模”“快进快出（48h/95%）”，展示现场可查。

**讲词**：
> “公安拿到的第一手数据就是又大又乱：这个文件 453 MB、507 万行、英文列名、多币种、
> 账号还拆成银行号+账号两列。平台不要求先回去手工整理：现场自动识别、字段映射、
> 流式清洗 5 万行只要 1–2 秒，洗完直接建图、跑规则、出报告。
> 原始文件只读，每次清洗生成可追溯的 `_stats.json`；全量 508 万行赛后跑，现场保节奏。”

**注意**：IBM 前几小时数据含大量 Reinvestment 自转账（付款=收款），清洗时被剔除属正常；
若评委问“为什么剔除这么多”，按上述口径解释。

## 3. 精简版与完整版

### 3.1 时间紧：5 分钟版

| 时间 | 页面 | 操作 |
| :--- | :--- | :--- |
| 0:00–0:20 | 调度总览 | 三机分工一句话 |
| 0:20–0:50 | 元智能体调度 | 内置 AML，**仅图工具分析**（约 10 秒），展示 93 可疑 |
| 0:50–1:10 | 规则与指标 | 复算指标（约 10 秒） |
| 1:10–2:00 | 数据接入 | 脏数据识别 + 453 MB 原始清洗 5 万行 |
| 2:00–3:00 | 调度页 → 图数据与工具/Neo4j 操作台 | 建图 + 图谱/快进快出复核 |
| 3:00–4:00 | 研判报告 | 展示已生成报告与证据下载 |
| 4:00–5:00 | 节点与工具 | 三节点状态、断网自检、收束 |

> 5 分钟版建议提前跑一次带 AI 报告的任务，让“研判报告”页有现成报告可展示；
> 现场不再等 30 秒模型生成。

### 3.2 时间充裕：12–15 分钟版

在 8 分钟版基础上增加：

- AI 报告逐 token 过程放慢讲解（Supervisor 路由、报告四段结构、防幻觉约束）；
- 数据资产页完整展示 7 套数据集卡片与评测（含 PaySim 换数据源：10 万行/14 万账户/归集 31）；
- 数据接入页演示“均匀抽样（跨全时段）”与 pandas 分析台（金额分布/按日趋势/表达式分析）；
- Neo4j Browser 登录 `192.168.0.199:7474` 演示图形视图（节点/关系）；
- 元智能体自主分析完整走 2–4 轮工具调用；
- 故障演练（可选）：关闭 Node2 展示规则模板兜底，再恢复。

## 4. 分角色操作卡

### 主讲（不碰键盘）

- 开场 30 秒讲清“第一台调度、第二台算力、第三台图数据”；
- 每个环节只讲“为什么做、怎么做、结果是什么”，不背 PPT；
- 遇到技术追问，点名对应操作员回答（“这个问题请 Node1/Node2/Node3 操作员回答”）；
- 时间控制：8 分钟版超时先砍“元智能体自主分析”，再砍“任务队列”。

### Node1 操作员（平台）

必须会做：加载数据源 → 加载目标 → 写/选指令 → 立即执行/仅图分析 → 任务结果页签 →
规则指标复算 → 数据资产“在调度页使用” → 数据接入选文件/执行清洗/建图。

### Node2 操作员（GPU）

必须会做：`nvidia-smi`（GPU 占用）、`ollama list` / `ollama ps`（模型加载）、
`python scripts/check_llm.py`（连通/速度）；报告生成时口头报“GPU 已占用、模型在推理”。

### Node3 操作员（图数据）

必须会做：Neo4j Browser 登录（`neo4j/fraud2026`）→ 执行 `MATCH (n:Account) RETURN count(n)`；
平台“Neo4j 操作台”跑预设“图谱规模/Top 入度/快进快出”；
解释“节点是账户、边是转账”。

## 5. 关键预期数字（现场核对用）

| 场景 | 数据规模 | 图谱 | 规则命中 | 指标 |
| :--- | :--- | :--- | :--- | :--- |
| 内置 AML（默认演示） | 42,175 笔 | 3,492 账户 / 42,175 边 | 归集 10 / 环形 12 / 快进 37 / 可疑 93 | 强证据精确率 1.000、召回 0.462；团伙 22/22 |
| IBM HI-Small 抽样 | 44,769 笔（原始 507.8 万） | 66,609 账户 / 44,769 边 | 归集 5 / 环形 5 / 快进 50 / 可疑 65 | 强证据精确率 1.000、最终清单 0.600；8 类模式 8/8 |
| IBM 原始清洗（现场 5 万行） | 原始 453.6 MB / 507.8 万行 | 49,843 账户 / 50,000 边 | 快进快出 50 | 清洗 0.7 秒；建图+规则 4–7 秒 |
| IBM 原始清洗（均匀抽样 10 万行） | 扫描全量 | 114,943 账户 / 89,747 边 | 快进快出 50 | 清洗约 34 秒（赛前可预跑） |
| PaySim 抽样 | 100,000 笔（原始 636.3 万） | 141,570 账户 / 100,000 边 | 归集 31 | 精确率 1.000 |

> 覆盖限制”，不要只报好看的数字。

## 6. 故障与降级预案

| 现象 | 立即处理 | 讲解兜底 |
| :--- | :--- | :--- |
| Node2 离线/很慢 | 关闭“执行 AI 研判报告”，改“仅图工具分析”；或直接展示已有报告 | “AI 不可达时自动降级规则模板报告，链路不中断” |
| Neo4j 离线 | 重新运行 `start-neo4j.bat`，等 `Started.`；`check_neo4j.py` 验证 | “图数据库本地进程，重启即可恢复” |
| 平台 8501 被占用 | `streamlit run app.py --server.port 8502`，浏览器切到 8502 | 现场切换即可 |
| 页面报错/白屏 | F5 刷新；仍异常看 `logs/streamlit.err.log`，重启平台 | 重启后数据不丢（落盘） |
| 数据源列表缺抽样 | 跑 `python scripts/prepare_datasets.py --all` | 用内置数据继续演示 |
| 大文件清洗卡顿 | 行数上限改“1 万行”，或换“格式样例”小文件 | “全量赛后跑，现场保节奏” |
| 断网自检显示可上网 | 检查是否连了外网/WiFi；说明演示要求物理断网 | “内网闭环，数据不出局” |
| 时间不够 | 立即切 5 分钟精简版 | 先保证主线：内置任务 + 规则指标 + 数据接入 |

**绝对不要现场做的操作**：不要重装依赖、不要清空 `data/new` 原始数据、不要改 `.env` 后不重启、
不要在演示中途 `reset_demo_data.py`（会清空当前图谱）。

## 7. 评委常见追问与回答口径

| 追问 | 回答 |
| :--- | :--- |
| 这就是元智能体吗？ | 主流程是稳定 Supervisor 固定流水线；工具调用实验台已真实跑通 Qwen3.5 自主 plan→act→observe→summarize，下一步接入主任务队列 |
| 规则阈值怎么来的？ | 在合成 AML 数据集上离线评测调参（精确率/召回率/F1/团伙召回），阈值与口径可现场复算 |
| 会不会用标签作弊？ | 标签字段在解析/清洗阶段直接丢弃，只有 `scripts/evaluate_*.py` 事后评测读取原始文件 |
| 数据这么大怎么跑？ | 服务器文件直读 + 分块流式清洗（20 万行/块）；现场 5 万行秒级，全量赛后跑 |
| 格式不一样怎么办？ | 自动识编码/分隔符/表头/列名，复合账号拼接，时间/金额多格式解析，界面可手工修正 |
| 召回率不高怎么办？ | 诚实说明：规则面向国内银行卡场景调参、模式覆盖有限；下一步模式扩充、规则口径配置化、GNN 扩展 |
| 为什么用 IBM/PaySim 数据？ | 真实案件数据涉密；用公开大规模合成数据验证工程链路，平台本身可直接接真实数据 |
| 断网能跑吗？ | 三机内网闭环，所有依赖本地部署；断网自检可证明外网不可达 |
| 创新点是什么？ | 三机协同调度、可解释图规则 + 证据链、大数据接入清洗、工具调用元智能体实验台 |
| 下一步做什么？ | 工具调用接入主任务队列 → 动态任务规划/失败重规划 → 规则口径可配置 → 图/表格扩展数据 |
