# 数据接入与清洗手册（真实一手数据怎么进平台）

> 面向：赛场演示、真实公安流水接入、评委质疑“你们是不是只会用内置数据”。
> 结论先说：**平台现在可以直接吃真实混乱数据**——几十 MB 到几百 MB 的 CSV/TSV/TXT/Excel，
> 自动识别编码/分隔符/列名，字段映射后流式清洗为统一流水，再建图、跑规则、出报告。

---

## 一、解决的真实问题

| 真实数据问题 | 平台做法 |
| :--- | :--- |
| 文件几百 MB，上传失败/内存爆 | **服务器文件直读**（无需上传）+ 分块流式清洗（20 万行/块），只写结果不整表进内存 |
| 编码乱（GBK/GB18030/UTF-8 BOM） | 自动探测编码，可手工修正 |
| 分隔符乱（逗号/分号/Tab/竖线） | 自动识别，可手工修正 |
| 表头缺失/列名乱 | 表头自动猜测 + 手工切换；列名中文/英文/带单位别名自动匹配 |
| 付款方是“银行+账号”两列 | 复合账号列：多选两列 + 拼接符（如 `012:800737690`） |
| 时间格式乱 | 字符串日期（含 `2025/1/2 13:05`、`2025年1月2日`）/ Unix 秒 / Unix 毫秒 / 步长（小时） |
| 金额带 ￥、千分位、负号括号 | 统一剥离后转数值 |
| 空账号、自转账、重复行 | 一键剔除，并在清洗报告中按原因计数 |
| 标签泄漏（Is Laundering / isFraud） | 标签字段**不进入**清洗输出，只允许离线评测脚本读取原始文件 |

## 二、平台操作流程（“数据接入”页）

1. **选择数据源**：服务器文件（推荐，几百 MB 秒开）或上传小文件；
2. **文件画像**：自动显示大小、行数、编码、分隔符、表头、列画像与“数据集类型提示”；
   识别不对时在“编码/分隔符/表头”处手工修正；
3. **字段映射**：自动建议时间/金额/付款账号/收款账号/摘要列；复合账号可多选两列并设置拼接符；
4. **预览清洗**：前 200 行先验证映射（显示读取/有效/剔除数量）；
5. **执行清洗**：选行数上限（1 万~全部）、抽样方式（前 N 行 / 均匀抽样）、是否剔除自转账/去重；
   进度条实时显示读取/写出行数；
6. **结果**：统一中文流水 `交易时间,金额,付款账号,收款账号,摘要` + 清洗报告 JSON；
   可直接下载，或点“在调度页用这份数据建图”；
7. **pandas 分析台**：对清洗后数据做金额分布、按日趋势、Top 账户分析与受限 pandas 表达式查询
   （无需另开 Jupyter）。

命令行等价方式：

```powershell
# IBM 原始 453 MB → 前 10 万行（约 2 秒）
python scripts/clean_data.py --input data/new/one/HI-Small_Trans.csv --rows 100000

# 均匀抽样（跨全时段，约 30 秒）
python scripts/clean_data.py --input data/new/one/HI-Small_Trans.csv --rows 100000 --uniform

# 演示脏数据（GBK + 分号 + ￥金额 + 混合日期 + 空账号 + 自转账 + 重复行）
python scripts/clean_data.py --input data/samples/messy_bank_flow.csv --output messy_demo
```

输出统一写入 `data/cleaned/`（git 忽略，可复现）；原始文件只读。

## 三、实测（本机 i7 / 16 GB，2026-11-26）

| 输入 | 原始规模 | 识别结果 | 清洗参数 | 结果 | 耗时 |
| :--- | ---: | :--- | :--- | :--- | ---: |
| `data/new/one/HI-Small_Trans.csv`（IBM AML） | 453.6 MB / 507.8 万行 | utf-8-sig、逗号、11 列、有表头 | 前 10 万行，剔自转账 | 10 万行 / 9.8 万账号；时间 2022-09-01~09-06 | 1.7 秒 |
| 同上 | 同上 | 同上 | 均匀抽样 10 万行（扫描全量） | 8.97 万行 / 11.4 万账号；时间 09-01~09-17 | 34 秒 |
| `data/new/paysim1/...log.csv`（PaySim） | 470.7 MB / 636.3 万行 | utf-8-sig、逗号、11 列 | 前 10 万行，step 按小时映射 | 10 万行 / 15.2 万账号 | 1.1 秒 |
| `data/samples/messy_bank_flow.csv`（演示脏数据） | 18 KB / 303 行 | **gb18030、分号**、5 列 | 全部清洗 | 284 行（剔除：空账号 5、自转账 11、重复 2） | 0.1 秒 |

清洗后直接建图：

```powershell
python main.py --no-report data/cleaned/HI-Small_Trans_clean.csv
# → 图谱 9.8 万账户 / 10 万边；快进快出命中 50 个账户（2026-11-26 实测）
```

## 四、赛场怎么讲（对着评委的 90 秒）

1. **拿出真实原始数据**：打开“数据接入”页，选 `data/new/one/HI-Small_Trans.csv`（453 MB），
   讲“这是 IBM 公开的 507 万笔银行流水原始文件，格式是英文列名、多币种、多银行账号”；
2. **展示自动画像**：编码、分隔符、行数、列名、复合账号自动识别；
3. **展示清洗**：点“执行清洗”（10 万行 1.7 秒），指出进度、剔除原因（自转账/空账号/重复）；
4. **展示建图**：跳转调度页用清洗产物建图、跑规则、生成报告；
5. **补充口径**：标签不进模型、原始文件只读、每次清洗有 `_stats.json` 可追溯；
   全量 508 万行可以赛后跑，现场演示用 10 万行保证节奏。

**评委可能追问 & 回答**：

- “数据格式不一样怎么办？” → 自动识别 + 字段映射 + 复合账号；平台已实测 IBM/PaySim/中文流水/GBK 脏数据。
- “数据太大怎么办？” → 服务器直读 + 分块流式清洗，不整表进内存；现场可前 N 行/均匀抽样。
- “是不是只会用内置数据？” → 现场用 `data/new` 原始文件走一遍清洗→建图→报告，内置数据只是快速基线。
- “会不会偷偷用标签？” → 标签字段在清洗时被丢弃，只有 `scripts/evaluate_*.py` 事后评测读取原始文件。

## 五、能力边界（诚实说明）

- 支持 CSV / TSV / TXT / Excel（.xlsx/.xls）；PDF/图片流水需先 OCR，不在本平台范围；
- 时间/金额解析覆盖常见写法，极少数自定义格式需先在上游转为标准格式；
- 去重为“块内去重”（20 万行/块），跨块重复请用全量模式或先 sort 后处理；
- 清洗过程记录在 `_stats.json`，但未做逐行审计日志（可后续扩展）；
- pandas 分析台是受限表达式沙箱（只允许 `df` / `pd`），不是完整 Jupyter；
  深度分析可对 `data/cleaned/*.csv` 直接用 JupyterLab 打开。
