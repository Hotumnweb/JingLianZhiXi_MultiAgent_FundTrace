# 数据资产使用手册（data/new 大数据集怎么用、赛场怎么展示）

> 适用：`data/new/` 下的 5 套公开数据集（约 2.5 GB）与平台“数据资产”页。
> 原则：**原始数据只作离线准备，现场只跑确定性抽样**；标签只用于事后评测，
> 不进入智能体输入（防标签泄漏）。
>
> 如果要回答“真实一手数据又大又乱怎么办”，不要只讲抽样——直接演示平台“数据接入”页：
> 选 `data/new` 原始 453 MB 文件 → 自动识别编码/分隔符/列名 → 字段映射 → 流式清洗 → 建图。
> 详见 [DATA_CLEANING_GUIDE.md](DATA_CLEANING_GUIDE.md)。

## 二、工作流（一次准备，现场直接用）

```powershell
conda activate fraud_agent
cd /d E:\JingLianZhiXi_MultiAgent_FundTrace

# 1) 生成全部抽样（约 45 秒；固定随机种子 20261125，可复现）
python scripts/prepare_datasets.py --all

# 2) 也可以只生成单个数据集
python scripts/prepare_datasets.py --dataset ibm-hi-small
python scripts/prepare_datasets.py --dataset paysim --rows 100000
python scripts/prepare_datasets.py --dataset elliptic --steps 20
```

生成结果写入 `data/prepared/`（已 git 忽略）：

| 文件 | 说明 |
| :--- | :--- |
| `<key>_flow.csv` | 统一中文流水：`交易时间,金额,付款账号,收款账号,摘要`，可直接被 `tools/parse_flow.py` 解析 |
| `<key>_labels.csv` | 账户级标签（`account,is_laundering` 或 `account,is_fraud`），只给评测脚本用 |
| `<key>_meta.json` | 抽样元数据：原始行数、抽样行数、标签数、抽样方式、生成时间 |
| `elliptic_edges.csv` / `elliptic_labels.csv` / `elliptic_overview.json` | Elliptic 子图与统计 |

**抽样策略**（写进 meta，可在平台“数据资产”页查看）：

- 流水类：标签交易（Is Laundering / isFraud）**全部保留**，正常交易固定种子抽样；
- PaySim 额外保留“诈骗账户关联交易”，补全“受害人 → 过渡账户 → 取现”资金链；
- 因此抽样中的洗钱/诈骗比例远高于真实比例，meta 中已注明“演示抽样，比例非真实”；
- Elliptic 按时间步抽子图，**无交易金额**，不进入资金流水规则主流程。

## 三、平台上怎么用

1. **数据资产页**：查看 7 套数据集卡片（规模、标签、许可、推荐用途）；
   - “生成/刷新抽样”：一键生成 `data/prepared/`；
   - “在调度页使用”：带着该数据源跳到调度页；
   - “抽样准备与预览”：查看样本前 20 行、IBM 8 类洗钱模式清单；
   - “抽样样本规则评测”：在已建好的抽样图谱上复算精确率/召回率与 IBM 模式覆盖。
2. **元智能体调度页**：数据源下拉选择“大数据抽样｜IBM AML · HI-Small · 44,769 笔”，
   加载目标 → 写侦查指令 → 选“仅执行图工具分析”（快）或带 AI 报告执行；
3. **图数据与工具 / Neo4j 操作台**：查看刚刚建好的抽样图谱；
4. **规则与指标页**：内置数据集的评测仍在这里复算。

## 四、实测参考（本机 16 GB / i7，2026-11-25）

| 抽样 | 行数 | 图谱规模 | 建图+规则耗时 | 规则命中 | 标签评测（强证据） |
| :--- | ---: | :--- | ---: | :--- | :--- |
| IBM HI-Small | 44,769 | 66,609 账户 / 44,769 边 | 约 6.4 秒 | 归集 5 / 环形链 5 / 快进快出 50 | 精确率 1.000；最终清单精确率 0.600 |
| PaySim | 100,000 | 141,570 账户 / 100,000 边 | 约 11.8 秒 | 归集 31 | 精确率 1.000 |
| 内置 AML | 42,175 | 3,492 账户 / 42,175 边 | 约 8.9 秒 | 93 个可疑账户 | 强证据 61/61，精确率 1.000 |

**IBM 模式覆盖**：8 类洗钱模式（FAN-IN / FAN-OUT / CYCLE / BIPARTITE / STACK / RANDOM /
GATHER-SCATTER / SCATTER-GATHER）在默认规则下 **8/8 类均有账户命中**。
但账户级召回很低（约 0.6%），原因是这套规则面向国内银行卡场景调参、模式覆盖有限——
答辩时要主动讲“精确率可信、召回靠模式扩充/口径配置”，不要只报召回。

快速复算命令（需先用该抽样建图）：

```powershell
python main.py --no-report data/prepared/ibm-hi-small_flow.csv   # 建图
python scripts/evaluate_prepared.py --dataset ibm-hi-small        # 复算指标 + 模式覆盖
```

## 五、赛场展示建议（8 分钟版）

| 时间 | 页面/动作 | 讲解要点 |
| :--- | :--- | :--- |
| 0:00–1:00 | 调度页跑内置 42,175 笔 | “解析 → 建图 → 三条规则 → 报告”稳定基线，指标现成 |
| 1:00–3:00 | 数据资产页 → 切 IBM HI-Small 抽样执行 | “508 万笔真实规模数据，抽样 4.5 万笔，6 秒建 6.6 万账户图谱” |
| 3:00–4:00 | 数据资产页复算指标 + 模式清单 | “IBM 官方 8 类洗钱模式全部命中；强证据精确率 100%；召回受限需要模式扩充” |
| 4:00–5:00 | 切 PaySim 抽样再跑一次 | “同一套代码不改，换移动支付数据 12 秒出结果” |
| 5:00–6:00 | 数据资产页 Elliptic / IEEE-CIS 卡片 | “图数据（GNN/社区发现）与表格对照是下一步能力边界” |
| 6:00–8:00 | 回到方法与局限、任务队列 | “标签不进模型、抽样比例非真实、规则口径可继续可配置化” |

**注意事项**：

- 现场不要直接扫描/选择 `data/new/` 原始文件（页面已屏蔽，避免误加载几百 MB）；
- 抽样固定种子，重复生成一致；比赛前预生成一次，现场只点“在调度页使用”；
- 若评委追问指标，主动区分“账户级规则命中”与“真实侦查召回”，并说明抽样放大了标签比例。
